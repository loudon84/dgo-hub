## Scope and source identity

This implementation covers M1-5D3 only. It was dispatched against baseline `3fbbd4d38f6568979b6b37b32d5322000f1ddb6a` with accepted D2 product `23cac1b6a3f00b595ecff085dc59f14dd771bc73`. The fixed-HEAD source bracketing in the final gates records that actual HEAD and unchanged file bytes before and after each command.

The implementation adds durable D claim/lease and retry state, bounded four-start processing with database-clock delays, heartbeat fencing, full candidate/currentness checks, and transactional canonical delete, durable outcome, receipt, progress, and outbox writes. The worker processes only a fully validated, frozen C cohort. Candidate operation UUIDs are allocated by `claim_etl_snapshot_delete_apply`: the claim transaction inserts one immutable operation row per `(candidate_id, entity, source_pk)` tuple using the table’s `gen_random_uuid()` default and unique key before the worker starts effects. The worker’s autocommit claim query returns only after this allocation transaction commits. Resume finds that same row under the unique tuple key, so it retains the same operation ID. Effect application is idempotent against the exact durable receipt. Source connector reads and physical business deletes are not introduced into D. API replay returns an existing valid APPLYING/COMPLETE approval result only under the bound identity, owner, epoch, scope, and currentness checks; it does not create a replacement approval. Above-threshold cohorts remain paused/disabled through approval and terminal processing; finalization does not activate them.

The schema contract was recorded before product edits at [m1-task5d3-schema-contract.md](E:/git/dgo-hub/.superpowers/sdd/2026-10-24-alpha1-m1-source-ingestion-implementation-plan/context/m1-task5d3-schema-contract.md). ## Fix1 review-round-one corrections (newer source identity)

The independent task review at `E:\git\dgo-hub\.superpowers\sdd\2026-10-24-alpha1-m1-source-ingestion-implementation-plan\task-5d3-review.md` identified two Important findings. Fix1 product and test source is committed at `7600189aa53fefc327a295f38948b87996bbb854`, based on review source `d98639be8e2af6baf3d7f6d1054fdc3d58cc550c`. The implementation remains limited to 5D3; migration 009 is still phase-owned and unreleased.

`claim_etl_snapshot_delete_apply` now handles an expired D lease before issuing a replacement claim. For an APPLYING run with a begun start and a still-present old claim token, starts 1, 2, and 3 persist DB-clock recovery delays of 5, 30, and 120 seconds, clear the old token/lease, and record `D_WORKER_LEASE_EXPIRED`. A fourth expired start is durably marked FAILED with `D_START_BUDGET_EXHAUSTED`; this preserves C COMPLETE, the source lifecycle/schedule fields, and any effects already committed by that start. `d_start_count=0` is not charged. A scheduled catchable retry has no old claim token and remains eligible when its persisted due time arrives; it is not misclassified as a dead worker. D token checks that use PL/pgSQL branches now use `IS DISTINCT FROM`, closing SQL NULL comparison gaps in currentness, effect recording, finalization, and retry. Begin/heartbeat writes and proof/member loads retain exact token and live-lease predicates.

For every apply, `check_etl_snapshot_delete_apply_current` keeps the established barrier → source → D run → candidate → source-registry order, then locks the exact current Owner's `auth_subject` row `FOR UPDATE` and checks `enabled` before the below-threshold early return. The PoolClient transaction retains this row lock through canonical aggregate, D outcome, and caller COMMIT. This adds no low-threshold D approval or pause. In the two-client test, an enabled Owner's disable UPDATE waited on a transaction-id lock while the authorized aggregate transaction was held at its pre-COMMIT gate; after release, the aggregate committed, then disable committed. The final D run was STALE on final currentness, while that below-threshold fixture's source/schedule remained ACTIVE/enabled and its C run COMPLETE; one canonical effect, receipt, and outbox row remained.
