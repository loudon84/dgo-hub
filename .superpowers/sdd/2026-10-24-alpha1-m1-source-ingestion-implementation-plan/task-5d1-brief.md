## Goal

Consume each eligible C `COMPLETE` snapshot once, maintain scoped complete-run absence/presence streaks, freeze the complete immutable candidate sets and exact denominators, and atomically reserve D source-busy state before C releases its active slot.

## Required behavior

1. Eligibility is based on successful C run status `COMPLETE`, exact immutable manifest/attempt, and frozen proof. Failed, stale, partial, invalid, interrupted, or otherwise incomplete runs neither increment nor reset any streak. A run counts once by tenant/source/run identity.
2. Derive scope from frozen config, field mapping, identity mapping, endpoint/profile, channel/domain, Owner/approval, entity set, and delete-contract proof. If an eligible complete run changes any scope component, it starts a new scope streak at 1; do not mix old facts. Retain prior facts for diagnostics. Presence in a successful complete run resets the matching full-key streak. Only frozen enabled entities participate.
3. Keys are complete source identity tuples scoped by tenant/source/entity; no display-name or partial-key joins. Candidate membership is the exact complete set of keys absent in two consecutive distinct eligible complete runs.
4. Consume backlogged runs in deterministic chronological order. Persist once-only consumption and update each run's own facts atomically. Do not let an older absence act over newer presence. Freeze/action only the latest current candidate cohort after newer pending complete-run presence facts have been processed. If a later active C run exists, candidate actions wait. Current proof/owner/newer-run drift stales old pending candidates instead of silently carrying forward approval.
5. C finish must create the D reservation in the same successful transaction as C `COMPLETE`, D `PENDING` or safe `SKIPPED`, and clearing the matching `active_run_id`. D reservation only applies to an absence-enabled `SNAPSHOT_OBSERVATION` contract. Other sources get a safe `SKIPPED` reconciliation summary and no synthetic `SOURCE_VERSION` delete.
6. Add source-busy checks to both manual API-019 and due-schedule admission. Busy states are `PENDING`, `AWAITING_OWNER`, `APPLYING`; they block new C admissions. Existing activation while D is unresolved returns the existing safe 409 conflict. D effects wait until no already-admitted C run is active and allow that C run to drain on its original frozen proof. The D busy marker is atomic with C finish, so no admission gap opens.
7. Record `completed_at` from DB time as the immutable second successful complete run time that establishes absence. This is inferred observed time, not source event time. Bind candidate to origin complete run(s), second run and its existing approved C observation. No wall-clock creation by worker and no sequence increment. OBS must be greater than last presence receipt; otherwise no candidate effect eligibility and status is safely blocked/stale for review.
8. Preserve C's observation high-water invariant: only reuse the latest allocated high-water observation when its latest successful COMPLETE binding has identical semantic digest and stable proof scope; older matching allocations behind a newer allocation are not eligible. The second C run may reuse its observation only if it remains greater than last presence.
9. Freeze all eligible entity candidate sets before any effect. Count exact active live canonical objects under the established global/source guard for the exact tenant/source/entity. Persist immutable baseline denominator and count. Use integer math `candidate_count * 100 > active_count * 5`. Empty denominator with zero candidates means no action. If any scoped set exceeds 5%, pause source and block every candidate action until every above-threshold set receives its own exact approval in D2. D1 never performs a candidate effect.
10. For future D3 rechecks, record `baseline_count` as immutable. Expected current active count equals `baseline_count - successful tombstones from this same candidate`. D's own committed actions do not stale remaining members. Any unrelated count or membership change is stale before another effect.
11. Preserve source pause and schedule-disabled state in D status/finalizers. Terminal D states (`FAILED`, `STALE`, `COMPLETE`, `SKIPPED`) release busy marker; no D finalizer enables schedule or activates a source.
