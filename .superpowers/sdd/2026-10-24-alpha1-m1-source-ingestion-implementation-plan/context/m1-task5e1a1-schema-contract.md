# M1-5E1a1 schema and worker contract

**Slice:** API-022 immutable snapshot manual recovery only. This contract is written before product source edits against accepted product pin `0112c661c4a543d614ba8685693a8384b8dc7201` and D closure `3f1661d293cc76feb4dce07dc3d091dfd2bb8154`.

## Public request and immutable result

`POST /hub/v1/admin/etl-runs/{id}/retry` requires a verified user principal with current `source:write` and an `Idempotency-Key` in the existing canonical syntax. The only JSON members are `failed_version` (canonical positive decimal string, persisted bigint CAS) and `reason` (trimmed nonempty, <=1000 Unicode codepoints). Tenant/source are derived from the locked original. A malformed body is rejected before database writes. Current caller scope and binding are rechecked while holding the security barrier and source fence, including on replay.

Accepted business result is immutable: `{operation_id, original_run_id, run_id, attempt_id, recovery_mode, status:'QUEUED'}`. Response adds `replayed`; replay returns the same IDs/mode/status and sets it true. The same idempotency tuple with a changed normalized request digest is 409. Current authorization/barriers/channel epoch are checked before reading/replaying it. No API response includes raw facts, credentials, or secrets.

Unique `(tenant,source,route,idempotency_key)`; unique child run and `(parent_run_id)` enforce one child per parent/family step. No credential secret or raw facts. 4. The child `etl_run_attempt` and its `attempt_id`/`operation_id` are preallocated QUEUED in the API admission transaction, so the immutable 202 result already names the reserved attempt. 5. Store API idempotency at tenant/source/route scope and pin body digest/result in the immutable operation. The DB acceptance function is `SECURITY DEFINER`, `search_path=pg_catalog,control`, PUBLIC revoked, `hub_api` only. It takes verified principal tuple and request tuple; locks `lock_security_barrier_fence()` FIRST, then exact source serialization, source/credential/channel/current-principal authority rows, original run and C/extraction claims, then any operation rows. ## Failure-version transition and lock order

Every API path: validate exact JSON and UUID/key syntax; acquire `lock_security_barrier_fence()` first; recheck `AuthService.assertCurrentPrincipal(...,'source:write')` under the current identity locks; then the admission function locks the exact source, current credential/tenant/channel and source rows, original run and active extraction/C continuation rows in the established compatible order; typed barriers and channel retirement are checked before failed-version comparison. Lock/eligibility/CAS failure creates no operation, child or audit mutation. Preserve the established source-wide exclusion so ordinary run admission, extraction, C, D reservation, manual recovery and future switch cannot overlap.

API admission records actual issuer, subject, verified tenant/user/auth epoch, current management scope and request ID from principal context. It never trusts tenant/source/actor in body. The DB operation and child insert commit in one transaction. Same-key replay first repeats current principal + source/barrier/epoch validation and then yields the immutable saved business result.

## FRESH_SCAN child

Use only when the original lacks a complete EXTRACTED manifest plus matching immutable semantic seal. Create an ordinary frozen-proof child `etl_run` with new UUID, QUEUED state and same exact proof/config facts as the failed original, but fresh child attempt, snapshot identity and stage keys. The normal snapshot worker discovers/claims it through the existing `snapshot-stage-store` and C worker lifecycle. It scans the full expected entity/relation set under the original frozen endpoint/credential/channel/profile; partial original pages remain diagnostics and are never used as a cursor. API-022 does not write stage facts or claim work. Fresh child completion uses normal C proof/seal/apply helpers and current security/credential/channel checks.

## SEALED_STAGE child loader and apply boundary

Select only if the original has `status=COMPLETE` extraction evidence, an EXTRACTED immutable manifest, a matching immutable semantic validation seal and any bound observation required for that original proof. The existing `read_etl_snapshot_c_proof` cannot service this directly: it requires same-run `COMPLETE` proof and stage rows keyed to that run/attempt; the child itself must own the live C claim and all mutable progress. Use narrow worker-only recovery loaders, never relax the general C functions:

- `read_etl_snapshot_recovery_manifest(text,text,uuid,uuid,uuid)` validates the live child B claim and immutable operation link, then returns the frozen original proof plus manifest/validation/observation linkage and exact digests. It checks the original COMPLETE extraction attempt and full semantic seal; the child run/attempt remains distinct.
- `read_etl_snapshot_recovery_stage_page(text,text,uuid,uuid,uuid,text,integer)` validates the same child claim and operation-bound original tuple for every page and returns the original page metadata/rows. The TypeScript B bridge rechecks exact page digests, writes the rows through ordinary child `write_etl_snapshot_page`, and creates a new child manifest using the preallocated child attempt and actual attempt operation ID plus explicit `recovery_source` provenance. Child C then runs the ordinary proof loader, semantic validation and child-local seal over those copied facts; it does not fabricate a C proof or accept arbitrary source coordinates. No upstream connector access occurs.
- `read_etl_snapshot_recovery_c_metadata(text,text,uuid,uuid,uuid)` is called only under a live child C claim and returns the immutable recovery link needed by the existing continuation proof. `get_etl_snapshot_recovery_prior_range(text,text,uuid,uuid,uuid,text,text)` resolves only a successful linked original aggregate range under a valid child claim; `record_etl_snapshot_recovery_reuse(text,text,uuid,uuid,uuid,text,text,bytea,bytea)` creates a child-local duplicate outcome with an FK to the exact original successful outcome. These functions are `SECURITY DEFINER`, fixed `search_path=pg_catalog,control`, PUBLIC revoked, and executable only by `hub_worker`. It never INSERTs/UPDATEs the original validation, observation, stage, manifest, C outcome/range or attempt rows. For SNAPSHOT_OBSERVATION, read the original observation sequence and preserve its allocation timestamp; do not insert a child observation row or allocate a new sequence. SEALED_STAGE is recovery completion only and is excluded from new D reservation/absence; preserve any preexisting original D facts.
- Before a canonical effect, loader looks up the original aggregate range. Skip only if its status is successful (`APPLIED`, `DUPLICATE`, or `IGNORED_STALE`) and its aggregate/proof digests match the recomputed original aggregate, backed by its exact existing receipt/range. A failed/quarantined/stale/retired outcome is never treated as success. Record recovery-local completion/reference under child claim. For unapplied aggregates, call the existing `applyCustomer` / `applyOrderAggregate` using the original frozen ApplyContext and caller-owned PoolClient; record the actual result and child progress atomically. Do not copy original ranges/outcomes into child coordinates or synthesize receipts.
- At each apply and finish, hold child claim token and lease, source serialization, security barrier, current principal/credential/tenant/channel/identity authority locks through canonical helper and outcome commit. Typed compromise/scope/tenant barriers and retired epochs fail before source-version comparison. Ordinary pause/config/admission-epoch drift alone does not replace/revoke original frozen proof.

If implementing the narrow stage fact loader still requires fabricating a child C seal, rewriting original proof, or bypassing the canonical helper's currentness checks, stop and report the seam conflict before product implementation.

## D absence lineage

Add nullable lineage root to the D reservation/cohort identity only where required to prevent a manual recovery family from creating a second distinct absence. A child reservation resolves the immutable operation's lineage root and is unique against any prior D absence reservation/observation for that root. A FRESH_SCAN child uses its own normal completed manifest, validation and actual observation, and at most the first successful complete snapshot for the immutable lineage root can establish a D cohort. SEALED_STAGE recovery completion creates no new D reservation or absence observation; it preserves any preexisting D facts. Replays/further descendants do not allocate another observation or reset D candidates/effects. Independent non-recovery successful full snapshots retain the existing D semantics. Never rewrite/reset D candidate/effect rows.

## SEALED_STAGE recovery clarification (2026-10-28)

The direct original-coordinate C loader proposed in the first draft was rejected at the implementation boundary: it would make child C consume source-coordinate proof while validation/progress ownership is child-coordinate, complicating truthful receipts and original-range reuse. The accepted seam is a worker-only trusted copy that preserves stage facts and page receipts exactly while deriving child-coordinate provenance.

The B worker, only while holding the child run's live claim and preallocated attempt, calls `control.read_etl_snapshot_recovery_stage_page(text,text,uuid,uuid,uuid,text,text,integer)` to stream the exact original page metadata and rows through existing child `write_etl_snapshot_page`. The loader resolves original run/attempt only from the immutable recovery operation, verifies original attempt COMPLETE, original EXTRACTED manifest digest and page coverage/digests, semantic validation seal, and required existing observation; it binds each page read to the live child claim and the frozen proof tuple. It never reads an arbitrary caller-selected source coordinate. The worker constructs a new child manifest by preserving source snapshot identity, relation coverage/counts, and every original page digest while setting the child's reserved `attempt_id` and actual attempt `operation_id`, and adding explicit `recovery_source` fields (original run, attempt, manifest digest, `copy_kind: EXACT_STAGE_FACTS`). It computes a new child manifest digest with the existing canonical digest helper and calls ordinary `complete_etl_snapshot_manifest`. Thus child C runs the normal proof loader, normal semantic validation and child-local seal over exact copied facts; no copied original manifest digest is mislabeled as child proof and no validation receipt is manufactured. The child operation retains the immutable original proof/manifest references.

For SNAPSHOT_OBSERVATION, after child validation matches the operation's original semantic and proof-scope digests, a narrow worker-only observation reader resolves the observation attached to that exact original run and returns its existing sequence value without allocating, inserting, or updating any child/original observation. SEALED_STAGE C completion bypasses D reservation because it is recovery completion, not a new source absence observation. Existing original D facts remain untouched.

Before any canonical helper, the child C worker resolves the linked original range. It skips only an exact digest/scope match whose original range points to an existing successful original outcome (`APPLIED`, `DUPLICATE`, `IGNORED_STALE`). A child-local recovery outcome records that reuse with an explicit FK to the original outcome; no original range/outcome/receipt is copied or mutated. Failed/quarantined/stale/retired original aggregates are reapplied through the ordinary canonical helper under the child claim/currentness fences. The ordinary child validation, claim, effect and progress paths remain authoritative.

FRESH_SCAN remains the ordinary worker scan path. The D reservation function atomically checks the immutable lineage root before clearing the active C slot; if a complete D cohort already exists for the root, it does not establish another cohort. SEALED_STAGE always establishes no new D cohort. No arbitrary C proof bypass or fabricated proof fallback is allowed; if the existing apply/finish seam cannot verify exact successful original receipt reuse, stop and report the conflict.
