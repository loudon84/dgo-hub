## Public contract

`GET /hub/v1/admin/quarantine` uses the existing strict success/error envelopes and verified user identity. Require source:read and the exact current enabled Owner of the selected same-tenant source. A source credential, a non-Owner manager, an old Owner, disabled subject, wrong tenant or insufficient scope receives the established safe denial without enumeration. Hold the existing barrier-first current-authority locks through the read transaction.

This management listing remains available to a valid current Owner when ordinary source admission is PAUSED, DRAFT or disabled; source admission state alone is not user read-authority revocation. Do not reuse an ACTIVE-only ingestion proof loader. Current tenant/subject/binding/scope denial still fails closed. Define the applicable typed read-security predicate in the schema contract rather than treating ordinary configuration drift as a blanket read barrier.

Query fields are exactly source_id (required, regex `^[A-Za-z0-9][A-Za-z0-9._:-]{0,255}$`), origin_kind (optional exact REST or SNAPSHOT), error_code (optional 1–96 characters matching `^[A-Z0-9_:-]+$`), limit (optional canonical positive decimal integer, default 20, maximum 100), and cursor (optional maximum1024 canonical base64url continuation). Unknown or repeated fields and invalid lexical forms return existing AUTH_INPUT_INVALID/400. Tenant and Owner are derived from verified context, never query/body. Error filters match exact stored safe machine codes; nullable original codes stay nullable rather than being fabricated.

The response contains items plus a nullable next_cursor. Each item returns only quarantine_id, origin_kind, source_id, entity, full qualified source identity (relation and parent_source_pk when present), origin job/item or run/attempt/outcome identifiers, immutable terminal status/error code, immutable creation time, frozen proof references/digests/revisions, and a typed safe dependency summary when evidence exists. Do not return raw batch bytes, item public_record, snapshot facts/pages, business payload, SQL/provider exception text, credentials, secrets, access tokens or connector details. Absent dependency proof yields an explicit unavailable/unknown machine status, never an invented dependency.

Order by immutable (created_at DESC, quarantine_id DESC), seek using the exact tuple, and bind continuation to tenant, source, origin/error filters, page size and current exact Owner/security authority. Recheck current authorization on every page. Invalid continuation is 400; stale currentness uses the established safe conflict/denial semantics pinned before dispatch. A page must not join a foreign source through a bare UUID. Publish only a continuation when more eligible records exist.

Controller ruling: use a strict versioned canonical cursor containing an explicitly ordered context SHA-256 and exact last ordering tuple, keeping bounded size independent of long source/issuer/subject values. The context digest includes verified tenant/source/issuer/subject, current DB-locked subject epoch, exact current Owner/revision, normalized filters and limit. This is an unsigned pagination cursor, not a cryptographic authorization token; a caller can alter its position, and all source/tenant/current-authority predicates are independently enforced server-side. Do not claim tamper-proof pagination or add a new signing secret. Preserve PostgreSQL microseconds in created_at using a canonical UTC six-fraction string; never round-trip a seek tuple through millisecond Date serialization. AUTH_CONTEXT_CHANGED/401 applies to a changed verified binding, AUTH_FORBIDDEN/403 to current Owner/scope denial, SOURCE_NOT_FOUND/404 to an inaccessible source using established source behavior, SOURCE_CONFLICT/409 to a syntactically valid stale authority/filter continuation, AUTH_UNAVAILABLE/503 to unavailable authorization.
