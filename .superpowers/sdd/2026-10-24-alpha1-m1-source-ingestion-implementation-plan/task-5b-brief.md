## Source transaction, paging, and destination stage

Create a narrow injected `PostgresSourceConnectionFactory` from the frozen profile, in-memory password, and deployment egress/TLS policy; one connection (`max: 1`), no ambient URL. Bind DNS-resolved/pinned peer to the approved host/profile and verify the peer before queries. Enterprise private addresses require explicit policy approval; fail closed if policy is unconfigured. Local fixtures use an injected `local_lab` factory limited to exact loopback. Keep the source connection read-only through separate source and hub DB pools; the production source role must have only required `SELECT` permissions. User values, page bounds and cursor controls are bound parameters. Validate and quote every schema/table/column identifier from the frozen profile/mapping.

Use one source session/transaction for all enabled customer, order-header and order-line reads:

```sql
BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY;
SET LOCAL TIME ZONE 'UTC';
```

Use a transaction-bound `NO SCROLL` cursor without `WITH HOLD`, fetched in bounded sequential pages per relation. Do not add a cursor package unless the accepted dependency tree proves it is needed. Every customer/order-header/order-line cursor is opened and consumed on the same dedicated connection and source transaction. No cursor or MVCC snapshot survives a lost source connection. Cast numeric, integer/bigint/version, decimal and timestamps to text in SQL before the driver can round them. Validate exact decimal/version grammar and preserve PostgreSQL fractional timestamp precision without JavaScript `Number` or millisecond `Date` conversion. For orders, stage complete header aggregates with line data (or parent/child rows keyed immutably and join-validated); preserve line order by the unique line key, with exact decimal strings.

Use an attempt-scoped private stage, minimally:

- Snapshot attempt state with monotonically increasing attempt ordinal (1–4), operation ID, current claim token/lease expiry, DB-clock availability, status/error, private source-snapshot provenance and immutable admission proof reference. A lease claim does not consume an attempt. In a separate durable `BEGIN_ATTEMPT` transaction, create/increment the attempt and mark it started before opening the source connection or issuing any source query; this is the four-start budget point and survives a crash.
- Immutable `etl_snapshot_stage_page` receipt keyed by `(tenant_key, source_id, run_id, attempt_id, entity, relation, page_no)`, with row count, first/last ordered key, and page digest.
- Immutable attempt-scoped `etl_snapshot_stage_record` keyed by `(tenant_key, source_id, run_id, attempt_id, entity, full source key[, line key])`, containing canonicalized-but-not-yet-validated JSON/text facts and source-key/version facts. Enforce uniqueness; a duplicate-key constraint violation fails the attempt. Do not use `ON CONFLICT DO UPDATE`, `DO NOTHING`, or conflict-ignore that can hide duplicates.
- Immutable completion manifest keyed to the same attempt, state `EXTRACTED`, enumerating the complete expected entities/relations, page receipts/counts/digests, private source-snapshot provenance, approved profile/mapping digests, and deterministic aggregate digest. It can be written only after each relation reaches EOF and all key/FK/required-column/page invariants pass. Keep the run in `VALIDATING`; do not introduce a fake run `READY` state before C.

Commit each destination page's records and page receipt atomically. A lost source transaction, cancellation, query error, lease loss or process crash leaves the attempt incomplete/diagnostic and its pages ineligible for absence, validation, or apply. Mark that attempt `INCOMPLETE`; a retry starts a fresh full source transaction and full scan under a new attempt ID. Never resume source paging from a checkpoint after reconnect. Keep incomplete attempt pages as evidence; do not automatically expire/delete them and do not silently mix attempts. The immutable source snapshot identity is the attempt UUID plus an optional SHA-256 of private `pg_current_snapshot()::text` captured inside the source transaction and bound to the frozen profile digest; it is provenance only, never a portable MVCC resume token or public API field. Only a complete immutable `EXTRACTED` manifest can be consumed by C. In B the ETL run must stop in `VALIDATING`; it must not become `READY`, `APPLYING` or `COMPLETE`.

## Claim, retry, lease, and scheduling

Reuse API-019's already-created queued run and existing schedule gate; never enqueue a second independent run queue. The runner claims from `control.etl_run` with source/tenant fence ordering, one active run per source, and `FOR UPDATE SKIP LOCKED`; issue a fresh random claim token for each attempt and require that token plus nonexpired lease on every heartbeat, page receipt, attempt/run status, and terminal update. Use database time for lease deadlines and scheduled/retry due checks. A stale token may not publish a page, complete a manifest, change a run, or start apply. Run one source scan at a time (`max:1` source connection, no parallel scans/apply). Keep every source connect/query outside any Hub transaction or global security-guard lock: perform the short guarded Hub claim, then a separate short guarded `BEGIN_ATTEMPT` transaction that checks typed barriers against the original run admission fence, close it, then connect/query upstream. Before each page receipt and final manifest, open a short Hub transaction, acquire `control.lock_security_barrier_fence()` first, verify claim token/lease and the original run admission fence against applicable typed barriers (`TENANT_DISABLED`, `CREDENTIAL_COMPROMISE`, `SOURCE_SCOPE_SECURITY_REMOVAL`, `CHANNEL_RETIRED`), persist the page/manifest, and commit before continuing source I/O. Use the original run proof/fence throughout attempts; the same typed-barrier check applies before `BEGIN_ATTEMPT`, each page receipt, and final manifest. Never hold that transaction while fetching from PostgreSQL. Ordinary pause/config/profile drift after successful API-019 admission does not by itself invalidate the frozen run proof; typed barriers newer than the original admission fence do. Do not replace the original proof/fence with a current profile/config or bypass typed barriers.

Use a bounded four-start budget: initial attempt plus at most three retries. The lease token fences every heartbeat, page/receipt transaction, completion manifest, and terminal update; a stale token cannot commit a page or publish completion. For observed transient failure, persist retry availability at 5, 30, then 120 seconds using database time. Permanent profile/permission/contract errors fail without retry. Process-crash/lease-expiry recovery marks the previous attempt incomplete using DB time and follows the same persisted bounded retry budget; every `BEGIN_ATTEMPT` including a crash counts, and exhaustion fails the run. Keep the 300-second per-source schedule and preserve the unique active-run gate. Do not claim that an in-process timer alone provides durable scheduling; API/manual admission, due gate, and strict worker wiring all need an independent acceptance trace.
