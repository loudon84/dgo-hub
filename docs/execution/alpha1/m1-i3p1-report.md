## Behavior and security

The read wrapper derives source from the quarantine under the authenticated tenant, checks the current designated owner, enabled tenant/subject/binding, auth epoch and `source:read`, and retains locks in the caller's transaction. Missing/cross-tenant origin is hidden; wrong owner and missing scope are denied. The application rechecks through `AuthService.assertCurrentPrincipal` in that transaction, and rejects source/agent principal shapes. The wrapper uses a private helper, so P2 can introduce a separate approve-guarded entry point without repeating original proof SQL or granting the helper to a runtime role. The candidate never exposes credential verifiers or raw batch bytes. Future public serialization must not dump the internal effective public record.

The reader validates the immutable job/item/quarantine/admission-audit links, import-only UPSERT/error scope, item ordinal and record fields, including timestamp equality. It calls the existing `verifyFrozenApplyContext` with the original context and handles its security barriers before deriving the candidate. Original non-null customer mappings remain resolved and make the order unavailable rather than becoming missing. Customer missing keys use `customerReferenceMappingKey` over the full referenced tuple; the referenced customer must already have an exact live identity. Partial customer mappings preserve and validate the original user/department target and reject a newer per-key remap fence. Existing reserved own UUIDs are returned without allocation. Source edits and pause do not invalidate the original proof.

DB UUID descriptors are canonical lowercase. The stored effective record is preserved, including uppercase event UUID spelling; UUID equality is semantic. The reader accepts the same hexadecimal UUID lexical shape as `validateHubBatch`, without adding version or variant restrictions. Source keys are not case-normalized. Revisions, fences, versions, and digests are represented as strings.
