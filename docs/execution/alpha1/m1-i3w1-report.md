## Changes and authority boundary

- The durable worker claims ordinary jobs and supported customer recovery children; flagged order children are filtered before the queue limit and a stale delivered order claim is stopped before hooks, adaptation, attempts, result and ACK. A customer discriminator never falls back to ordinary REST recovery authority.
- `applyImportRecoveryCustomer(client, scope)` accepts only tenant/source/job/ordinal/item-operation/claim scope and invokes the accepted W0 reader in the same apply transaction. That reader independently validates the immutable original and accepted binding proofs and holds current actor, exact OIDC binding, Owner, source and identity locks. The original proof, effective record, source version, digest and raw batch remain original. The private customer mechanics share the existing receipt/version/identity/canonical-write path with ordinary `applyCustomer` and require the reserved UUID.
- For each key the original mapping and fence remain authoritative when originally resolved; only the exact confirmed originally missing key selects the binding mapping and its fence. Current remaps and target eligibility are checked before recovery duplicate/stale shortcuts. The original/binding contexts and the ordinary API are not replaceable by caller-supplied proof or target JSON.
- Additive migration `018_import_recovery_customer_apply.sql` provides a scope-only, worker-only `control.record_import_recovery_customer_owner_change(text,text,uuid,integer,uuid,uuid)`. It derives operation, proofs, mappings and targets inside SQL, calls 017 for claim/authority, and checks the exact current projection plus same-transaction receipt/outbox before private shared ownership effects. Ordinary `control.record_canonical_customer_owner_change(...)` keeps its existing call signature and uses the same private proof/effect mechanics. Private functions have no application-role EXECUTE. Same-TX affected subjects receive the existing distinct-user auth-epoch increments and the ownership audit/reference updates.
- The existing shared claim renewal now requires the token still be unacknowledged and live by PostgreSQL clock at its UPDATE; it cannot revive a lease that expired after the locking SELECT. A non-renewing exact claim/clock check runs after the final precommit hook. Canonical customer, reserved identity, references, receipt, canonical outbox, audit, subject epochs, item and job summary commit together. Processing-outbox ACK is a later claim-checked transaction. A terminal reclaim ACKs without a new attempt or business effects.
- Recovery authority/context/proof errors become bounded `QUARANTINED` codes; per-key errors use existing mapping/target codes. Version results preserve `APPLIED`, `DUPLICATE`, `IGNORED_STALE` and `SOURCE_VERSION_CONFLICT`. Lost claims do not write with the old token; other failures retain the existing retry budget. GET returns a bounded receipt only for an APPLIED child whose current receipt exactly matches the operation; duplicate, stale, quarantine, and an advanced receipt expose null.

The root ruling does not relax external revocation: the exact frozen actor epoch is checked before effects under locks retained through commit. The same authorized transaction may increment the actor's epoch through the established ownership effects. There is no epoch override, tolerance, compensating reset or ignored authority error.
