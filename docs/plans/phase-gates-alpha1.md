# Alpha.1 阶段门禁检查表

更新：2026-10-23。执行依据为 [优化后的路线计划](2026-10-23-0745-feat-alpha1-implementation-roadmap-plan.md)、主 PRD 第 20–29 章及附录 B/C/D。本文是后续执行检查表；复选框未勾选，不表示已经执行或通过。

## 1. 状态与证据规则

- 实施单元沿用 PRD：`planned / implemented / verified / blocked`；静态看到代码只能支持 implemented，不能支持 verified。
- 每项实际验收使用 `PASS / FAIL / BLOCKED / SKIPPED / NOT_RUN`；只有 PASS 计入阶段退出。
- 本地合成测试与现场测试分别记录 `environment_kind` 和 `input_kind`。前次会话中的通过报告是待重跑归档的线索，不替代证据文件。
- 正式阶段退出要同时具备：前置阶段 verified、该阶段验收 PASS、证据摘要有效、批准与环境合同适用。仅满足开发入口可以开展对应任务，不能据此标记阶段完成。
- 环境或身份未提供记 BLOCKED；没有执行记 NOT_RUN；不填充虚构的实际结果、签署人或时间。

## 2. 共用门禁

- [ ] 当前产品合同批准状态和缺项已记录；没有将 REVIEW 自动改为 APPROVED_FOR_PLAN。
- [ ] 环境合同区分本地隔离实验与现场，记录来源副本授权、IdP、测试身份、秘密引用、地址和备份责任人。
- [ ] `integration-service/` 是唯一集成实现目录；七个模块继续复用；建议目录与实际目录有映射。
- [ ] `deployment.lock.json` 对应实际运行的源码、镜像 digest、配置和探测结果；不存在空 digest 或以 tag/工作区 tip 代替运行身份。
- [ ] 验收记录包含 acceptance_id、requirement_ids、test_ids、状态、命令、退出码、时间、版本、输入、独立期望值、实际值和带摘要的证据文件。

## 3. M0：基线与安全边界

**开发入口：** 已有工程可做差距核对和隔离实验加固。**正式验收入口：** 共用门禁中的批准与环境输入满足对应合同。

- [ ] 钉扎 PRD 的 OpenMetadata、Helix、Hasura 基线，分别记录参考源码和实际部署身份；不直接切换可能被其他工作使用的上游目录。
- [ ] 四进程分离；Hasura 管理凭据仅 Publisher 持有；MCP 没有业务写权，数据库角色相互越权访问被拒。
- [ ] 从销售网视角探测 Hasura、Helix、数据库及 OpenMetadata 管理口，均不构成销售查询旁路；回环端口限制不能单独作为该证据。
- [ ] 来源身份与个人身份分离；有效身份来自服务端绑定；请求注入 tenant/user/role 不改变授权主体。
- [ ] 企业登录与用户绑定凭据方案完成基础验证，凭据创建/过期/撤销及 epoch 接口可供 M2/M4 使用。
- [ ] A-ARCH-001 / N-ARCH-001 和 A-AUTH-001 / N-AUTH-001 的基础子集有证据；完整身份在途撤销在 M2/M4 验收。

**退出：** 上述基础子集和 lock 有效，M0 才可 verified。未通过项写明负责人和缺项，不以本地容器启动替代。

## 4. M1：上游接入与标准数据

**开发入口：** M0 身份、来源及数据合同可供开发；允许利用现有接入代码补齐。**正式验收入口：** M0 verified。

- [ ] 来源/映射经测试、审批、激活；字段映射及删除合同可版本化，修改后回到待验证状态。
- [ ] hub.v1 批次接入、202/job_id、逐项回执、409 同键异内容符合 PRD；单条演示接口不能冒充批量合同。
- [ ] 同版本同内容去重、同版本异内容隔离；订单头/完整明细/回执/outbox 原子应用；跨租户关联被拒。
- [ ] PostgreSQL 与 SQL Server 适配按范围完成；全量快照、增量启用条件、删除对账、channel_epoch 和失败水位符合合同。
- [ ] 附录 C.4 独立 Oracle 与实际结果对账一致；失败重试、隔离和人工重放有可核对结果。
- [ ] A-SRC/ING/ETL/DATA-001、对应 N-* 及 FI-01–FI-05 通过并归档。

**退出：** M1 的 A/N/FI 全部 PASS；真实来源合同和后续 Golden Consumer 输入另记，不用合成数据替代。

## 5. M2：Hasura 授权查询与权限执行基础

**开发入口：** M1 稳定模型、M0 身份合同；权限执行基础提前供 M5 权限页面使用。**正式验收入口：** M1 verified。

- [ ] `sales` 本人范围与 `sales_manager` 部门范围成立；订单和明细沿客户授权关系判定；归属变化及删除不会留下旧授权。
- [ ] 固定查询、列白名单、脱敏、嵌套关系及跨租户聚合均通过正负例。
- [ ] 301 笔订单、取消状态、多币种、签名游标、日期/条数/响应上限符合 PRD；汇总不受列表截断影响。
- [ ] Publisher 有实例级发布锁、审批 digest/revision、T0/candidate/observed、漂移判断、CAS、canary、APPLIED 回执及恢复状态。
- [ ] 发布失败、未知结果、撤权失败保持关闸；恢复不会放宽撤权；客户转交/凭据撤销发生在途时丢弃未交付结果。
- [ ] A-SEC/API-001、N-SEC/API-001 通过；A-POL/N-POL-001 的引擎部分及 FI-06–FI-10 有证据；完整 UI 工作流留到 M5 复核。

**退出：** A-SEC/API 和全部相关越权 N 用例 PASS；执行器恢复缺口作为阻塞项，不能延至接入真实消费者之后再解决。

## 6. M3：治理、本体与绑定发布

**开发入口：** M1/M2 的资产和查询合同稳定，可先做适配开发。**正式验收入口：** M1、M2 verified。

- [ ] OpenMetadata 登记资产、质量和血缘；重复同步不重复创建，保留人工描述；未执行质量检查保持 NOT_RUN。
- [ ] Helix 每租户工作区、受限投影、三对象两关系、模型提案/校验/发布/导出按合同执行；网络可达接口的 Bearer 边界有拒绝证据。
- [ ] Binding Release 不可变，包含 generation/export digest、资产 UUID、映射、关系、模板、指标版本及批准信息。
- [ ] 查询上下文来自已发布绑定和有效策略；断开上游时新发布被阻断，已发布查询不走旁路。
- [ ] A-GOV/ONT/PUB-001、对应 N-*、FI-11 通过；投影时点与业务副本查询时点明确区分。

**退出：** 上述验收全部 PASS。只读 GET 和字段存在性验证不足以关闭本阶段。

## 7. M4：Hermes 与真实业务联通

**开发入口：** 可提前准备 Hermes 版本、受管配置、问句及用户身份。**正式验收入口：** M2、M3 verified，来源 Owner 批准的真实测试输入可用。

- [ ] 恰好五工具的 initialize/tools/list/tools/call、参数、structuredContent、错误与审计合同通过。
- [ ] 用户绑定随机 Bearer 凭据可过期、撤销；服务端签发限定 Hasura JWT；不能共用用户凭据或由参数伪造身份。
- [ ] 两名销售及一名部门经理具备独立测试身份，Hermes Profile 与其映射清楚；记录 Hermes 实际版本及配置摘要。
- [ ] CRM/订单批准快照与独立 Oracle、工具实际输出、Hermes 回答三方对账。
- [ ] A-MCP/AGENT-001、N-MCP/AGENT-001 和完整 A-AUTH/N-AUTH 通过，含在途撤销及 FI-10、审计失败 FI-12。
- [ ] `golden-consumer/` 保存真实消费端证据；无真实系统时状态为 BLOCKED。

**退出：** 协议验收与真实 Golden Consumer 均 PASS；本地 SDK 调用通过不等于 Hermes 验收通过。

## 8. M5：四页面增量交付与完整 UI 收口

**开发入口：** 对应 API/schema/状态合同已冻结，可分别交付页面。**正式验收入口：** M0–M4 verified。

- [ ] 接入页随 M1 联调；本体绑定页随 M3 联调；权限页随 M2 执行器联调；Agent 页随 M4 联调。
- [ ] Spec 的 P1/P2/P3/P4 映射到主 PRD P02–P04/P06–P07/P08–P09/P10–P11；补齐来源配置、字段映射、模型提案、凭据领取撤销等未覆盖动作。
- [ ] P01 总览、P05 原生治理复用与 P12 运行/交付记录有明确入口和用例；不因四页聚合而删除这些能力。

- [ ] A-UI/POL/OBS-001、N-UI/POL/OBS-001 和 FI-12 全部 PASS；直接绕过按钮调用写 API 仍被拒。

## 9. M6：交付与放行

**开发入口：** 证据采集和恢复用例从 M0 即可建设。**正式验收入口：** M0–M5 verified。

- [ ] 固定环境执行性能、备份和隔离恢复；恢复对象、授权、金额及 gate 状态符合附录 D。
- [ ] 18 个 required A、18 个 N 与 FI-01–FI-12 均有有效证据，且全部 PASS。
- [ ] 每项 required 的证据路径、文件摘要、运行版本和输入类型校验通过；无有效证据的 PASS 被拒。
- [ ] 真实 Golden Consumer 存在且匹配来源/消费者版本；fixture/sample/占位材料不能替代。
- [ ] 无 RECOVERY_REQUIRED、未解决漂移或未关闭阻塞项；A-OPS/EVID-001、N-OPS/EVID-001 通过。
- [ ] Gate 对缺证据、摘要被改、SKIPPED/NOT_RUN/BLOCKED 和 synthetic-as-golden 均返回非 0；只有完整有效结果返回 0。

**退出：** Release Gate 完整 PASS 后才标 Alpha.1 可放行。验收脚本自身的样例通过不证明产品放行。
